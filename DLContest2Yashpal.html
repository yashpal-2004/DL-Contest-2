13 · Transfer Learning & Why ViT pretrained · feature extraction · freezing · fine-tuning · augmentation · CNN limits
In one minute

Transfer learning = reuse a network that was already trained on a huge dataset (like ImageNet, 1.2 million images, 1000 classes) as the starting point for your own, smaller problem. Early layers already know edges, colours and textures, which every image task needs. You freeze them (or train them gently) and only train a new head for your classes. Two modes: feature extraction (backbone frozen, train only the new head) and fine-tuning (unfreeze some or all backbone layers and train with a small learning rate). Data augmentation makes the small dataset look bigger. CNNs have limits (local view, fixed inductive bias), which is the motivation for the Vision Transformer (ViT).

13.1 The problem transfer learning solves

Training a deep CNN from scratch needs lots of labelled data (hundreds of thousands of images), lots of compute (days on GPUs) and careful tuning. Most real projects (classify 800 photos of crop diseases, 2,000 X-rays) have neither. With a few hundred images a big network simply memorises them (high variance, i.e. overfitting).

The key observation: features learned on a big dataset are reusable. A network trained on ImageNet has learned a hierarchy:

LayersWhat they detectReusable for a new task?
Early (conv1, conv2)Edges, corners, colour blobs, simple texturesAlmost always (general)
MiddlePatterns, repeated textures, object parts (wheel, eye, fur)Usually
Late (last conv block)Whole-object, ImageNet-specific features (dog breed, car model)Only if your task is similar (specific)
Final FC / softmax (1000 classes)The ImageNet class scoresNever: replace it
General → specific. The deeper the layer, the more task-specific it is. This one idea decides which layers to freeze.

13.2 Pretrained models

A pretrained model is a network (architecture + learned weights) already trained on a large dataset, usually ImageNet. Examples from your lectures: VGG, ResNet, Inception, MobileNet, EfficientNet (and for language, BERT/GPT). Libraries ship them: torchvision.models.resnet18(weights=...), tf.keras.applications.MobileNetV2(weights='imagenet').

  • Backbone / base / feature extractor = the convolutional part (everything before the classifier).
  • Head / top / classifier = the final dense layers that map features to classes. This is what you replace.
  • include_top=False (Keras) means: load the backbone without the original 1000-class head.
  • Input rules: feed the size and the normalisation the model was trained with (for ImageNet models: usually 224×224 and mean (0.485, 0.456, 0.406), std (0.229, 0.224, 0.225)). A mismatch silently ruins the features.

13.3 Feature extraction (the backbone is frozen)

Pass your images through the frozen backbone to get a feature vector per image (for ResNet-50 that is 2,048 numbers after global average pooling). Train only a small new classifier on those vectors. The backbone is a fixed function; only the head learns.

Feature extraction image → [ frozen backbone ] → feature vector (e.g. 2048) → [ NEW head: Dense(num_classes) + softmax ] → prediction trainable parameters = ONLY the head = 2048 × num_classes + num_classes (e.g. 10 classes: 20,490)
  • Fast and cheap: you can even compute the features once, cache them, and train the head in seconds.
  • Safe for small data: very few trainable parameters → low overfitting risk.
  • Weakness: the features cannot adapt to your domain (e.g. medical images that look nothing like ImageNet).

13.4 Layer freezing

Freezing a layer means its weights get no gradient update. Keras: layer.trainable = False. PyTorch: p.requires_grad = False for its parameters (and don't give them to the optimizer). Frozen weights still take part in the forward pass; they just never change. Gradients are still computed through them if a trainable layer sits before them, but not for them.

BatchNorm trap. A frozen BatchNorm layer should also be kept in inference mode (use the stored running mean/variance, do not update them). If it keeps running in training mode, it replaces the pretrained statistics with statistics of your tiny dataset and the pretrained features degrade. (Keras: call the base with training=False; PyTorch: model.eval() for those layers.)
  • Frozen weights ≠ removed. They are still counted in "total params" but reported as non-trainable.
  • Freeze order: freeze the early layers (general features), unfreeze the late layers (specific features). Never the reverse.
  • Changing trainable in Keras only takes effect after you re-compile the model.

13.5 Fine-tuning

Fine-tuning = start from pretrained weights, then unfreeze some (or all) backbone layers and continue training on your data. The standard recipe has two stages:

  1. Stage 1 (warm-up the head): freeze the whole backbone, train the new head until it is reasonable. (A random head would send large, garbage gradients into the backbone.)
  2. Stage 2 (gentle unfreeze): unfreeze the last few blocks and train with a very small learning rate (for example 10⁻⁵ to 10⁻⁴, about 10× to 100× smaller than the head's 10⁻³). Re-compile after changing trainable.
Why a small learning rate? The pretrained weights are already good. A large step would wreck them ("catastrophic forgetting"). Discriminative learning rates (smaller LR for earlier layers, larger for the head) are common.

13.6 Which strategy to use? (dataset size × similarity)

Your dataSimilar to pretraining dataVery different from pretraining data
SmallFeature extraction (train only a new head). Fine-tuning would overfit.Freeze early layers, fine-tune a few later layers with tiny LR, or take features from an earlier (more general) layer. Use strong augmentation.
LargeFine-tune most or all layers with a small LR (fast convergence).Fine-tune everything (or even train from scratch). Pretrained weights are still a better initialisation than random.
Exam trap: "Small dataset + very different domain" is the hard cell. The answer is not "train from scratch" (too little data) and not "freeze everything" (features don't fit). It is: freeze the early general layers, train the later layers + head carefully.

13.7 Data augmentation

Data augmentation creates new, slightly different training examples by applying label-preserving random transformations to the existing ones. The network never sees exactly the same image twice, so it cannot just memorise. It is a regulariser (reduces variance / overfitting).

TypeExamplesCareful about
Geometrichorizontal flip, small rotation, random crop / resized crop, translation, zoomDon't vertically flip or rotate 180° where up/down matters (digits 6 vs 9, text, X-rays with side markers)
Colour / photometricbrightness, contrast, saturation, hue jitter, grayscale, blur, noiseDon't change colour if colour IS the label (ripe vs unripe fruit)
Mix-basedCutout (erase a patch), Mixup (blend two images and labels), CutMixLabels are mixed too
  • Applied only to the training set. Validation and test images are only resized/normalised, never randomly altered (otherwise your measured accuracy is noisy and not comparable).
  • Done on the fly each epoch, so the stored dataset size does not grow. It increases the diversity the network sees, not the number of real, independent samples.
  • It adds invariance you want (a flipped cat is still a cat) and fights overfitting. It does not fix underfitting (high bias).
  • Keras: RandomFlip, RandomRotation, RandomZoom layers (active only in training). PyTorch: transforms.RandomHorizontalFlip(), RandomResizedCrop(224), ColorJitter().

13.8 Limitations of CNNs (the motivation for Vision Transformers)

CNNs are brilliant, but their built-in assumptions (inductive biases) are also their limits:

  • Local receptive field. A 3×3 kernel only sees a small neighbourhood. To relate two far-apart regions (a dog's head and tail) the signal must travel through many layers; the effective receptive field grows only slowly with depth.
  • No true global context in early layers. Global reasoning only appears near the end.
  • Weights shared everywhere (same kernel at every position): great for efficiency, but the layer cannot treat "top-left" differently from "bottom-right" content-dependently. The filter is fixed after training and does not change with the input.
  • Pooling throws away position/pose information. Some invariance to small shifts only; not invariant to rotation or scale unless taught by augmentation.
  • Fixed input assumptions (regular grid, usually fixed size) and a texture bias (CNNs often lean on texture rather than shape).

Vision Transformer (ViT) is the response: cut the image into patches, treat each patch like a "word" token, add position embeddings, and run a Transformer encoder. Self-attention connects every patch to every other patch in the very first layer (global receptive field).

ViT pipeline (ViT-Base/16 on a 224×224×3 image) patches = (224/16) × (224/16) = 14 × 14 = 196 patches each patch has 16·16·3 = 768 numbers each patch → linear projection → 768-dim token prepend a learnable [CLS] token → 197 tokens add position embeddings → Transformer encoder (self-attention + MLP, repeated) → [CLS] output → classifier self-attention cost grows as n²: 197² = 38,809 pairwise scores per head
CNNViT
Building blockConvolution (local kernel, shared weights)Self-attention on patch tokens
Receptive fieldLocal, grows with depthGlobal from layer 1
Inductive biasStrong (locality, translation equivariance)Weak (must learn from data)

Careful: ViT is not "better in every case". The motivation is global context and scalability. With little data its weak inductive bias hurts, which is exactly why pretrained ViTs plus transfer learning are used.

Common mistakes

"Freezing means the layer is skipped." No. A frozen layer still runs in the forward pass; only its weights stop updating.
Using a large learning rate when fine-tuning. It destroys the pretrained weights. Use a small LR (about 10⁻⁵ to 10⁻⁴).
Fine-tuning from a randomly initialised head straight away. Train the head first (stage 1), then unfreeze.
Augmenting the validation/test set. Only the training set is augmented.
Forgetting to replace the final layer. The pretrained head has 1000 outputs; your task has N.
Saying "augmentation increases the number of images in the dataset." It creates varied views on the fly; it does not add new independent real samples.
Thinking CNNs have no global view at all. They do, but only after many layers. ViT gets it in the first layer.

How to solve transfer-learning numericals

  1. Trainable parameters in feature extraction = parameters of the new head only: (features × classes) + classes for one Dense layer. Backbone = non-trainable.
  2. Total parameters = backbone (frozen) + head. Trainable / non-trainable are reported separately.
  3. Fine-tuning count: trainable = head + the unfrozen backbone layers. Count each unfrozen conv as k×k×C_in×C_out + C_out.
  4. ViT tokens: patches = (H/P)×(W/P); token dimension = P×P×channels (before projection); add 1 for the [CLS] token; attention matrix = tokens².
  5. Replacing the head: old head weights are thrown away; the new one is randomly initialised.

14 · Recurrent Neural Networks sequences · hidden state · unrolling · BPTT · long-term dependencies
In one minute

In sequential data the order carries meaning ("dog bites man" ≠ "man bites dog"). A dense network wants a fixed-size input and ignores order. A Recurrent Neural Network (RNN) reads one element at a time and keeps a hidden state ht (a running memory). The same weights are reused at every time step: ht = tanh(xtWxh + ht−1Whh + bh). "Unrolling" draws the loop as a chain of copies. Training uses backpropagation through time (BPTT), and the long chain of multiplications causes vanishing/exploding gradients, so a plain RNN forgets long-term dependencies. That failure is why LSTM/GRU exist (next topic).

14.1 Sequential data: what and why order matters

A sequence is a list of items where position and order change the meaning. Examples: text (words), time series (stock prices, sensor readings), audio (waveform frames), video (frames), DNA/protein sequences, clickstreams, music notes.

SentenceMeaning
dog bites manan ordinary news item
man bites doga headline
not goodnegative
not badmildly positive

The words are the same in the first pair, only the order differs. In the second pair, the word that came before flips the sentiment. A model must use order and context.

14.2 Why a plain dense network (ANN) fails on sequences

  • Fixed input width. A dense layer has a fixed number of inputs, but sentences have different lengths. You must pad/truncate everything to one length.
  • Wasted computation on padding (all those zero positions still get weights).
  • Cannot handle longer inputs at inference. A sequence longer than the training length simply does not fit.
  • Order is not modelled. If you feed a bag-of-words count, order is gone; if you flatten positions, the model learns separate weights for "word at position 3" vs "position 4" and does not share what it learned about a word across positions.
  • Too many parameters for long inputs (weights grow with length).

An RNN fixes these: one small set of weights reused at every step (parameter sharing over time, like a CNN shares a kernel over space), any sequence length, and a memory that carries context forward.

14.3 The RNN cell

At each time step t the cell takes the current input xt and the previous hidden state ht−1, and produces a new hidden state ht. Think of ht as a summary of everything read so far.

Simple (vanilla) RNN ht = tanh( xt Wxh + ht−1 Whh + bh ) h0 = 0 (all zeros) yt = g( ht Why + by ) g = sigmoid (binary), softmax (multi-class), linear (regression) shapes: xt : 1×D ht : 1×H yt : 1×O Wxh : D×H Whh : H×H Why : H×O bh : H by : O D = input features per step, H = hidden units (size of memory), O = outputs
  • tanh keeps ht in (−1, 1) so the state cannot blow up through the activation itself.
  • Whh is the "memory" matrix: it mixes the previous state into the new one. It is H×H (square) because state in and state out have the same size.
  • The hidden size H is a design choice, not tied to the sequence length T.

14.4 Unrolling through time

The RNN has a loop. To understand and train it we unroll the loop: draw one copy of the cell per time step, h₀ → h₁ → h₂ → … → hT.

The most-tested point: all the copies are the same cell with the same (shared) weights, NOT separate networks. A longer sequence means more computation (more steps) but NOT more parameters. The parameter count has no T in it.
Parameters of a simple RNN layer + output layer recurrent layer: D·H (Wxh) + H·H (Whh) + H (bh) = H(D + H + 1) output layer: H·O (Why) + O (by) = O(H + 1) total = H(D + H + 1) + O(H + 1) (independent of sequence length T)

14.6 Training: backpropagation through time (BPTT)

Unroll the network over T steps, compute the loss (sum or mean over the steps that have a target), then apply ordinary backprop on the unrolled graph. Because the same weights appear at every step, their gradient is the sum of the gradient contributions from every time step.

Gradient from a late loss back to an early state ∂hT/∂h1 = Πt=2..T ∂ht/∂ht−1 = Πt=2..T diag(1 − ht²) · WhhT → a product of (T−1) similar matrices.

14.7 Long-term dependencies and vanishing / exploding gradients

Some predictions need information from far back: "The cats that I saw at the zoo yesterday were sleeping" (singular/plural verb depends on a word 8 steps earlier). A long product of matrices behaves like a number raised to a large power:

Factor per stepAfter 10 stepsAfter 20 stepsResult
0.50.000980.00000095Vanishes: early steps get no learning signal
0.90.3490.122Slowly fades
1.011Stable (hard to maintain)
1.557.73,325Explodes: huge, unstable updates (NaN)
  • Vanishing gradients: the typical factor is < 1 (tanh′ ≤ 1 and often small, Whh has small singular values). The network cannot learn that an early word matters. This is the long-term dependency problem.
  • Exploding gradients: factor > 1 → loss jumps, NaN. Fix: gradient clipping (rescale the gradient if its norm exceeds a threshold).
  • Vanishing is harder to fix: use gated cells (LSTM/GRU), good initialisation (identity/orthogonal Whh), ReLU-type activations with care, or shorter truncated BPTT windows.
  • Vanilla RNN also processes step by step: it cannot be parallelised over time, which makes it slow on long sequences (a reason Transformers replaced it).
Clipping fixes explosion, not vanishing. This pair is a favourite exam trap.

14.8 Practical points (Keras RNN notebook)

  • Input shape is 3D: (batch, timesteps, features). For text with an Embedding layer: tokens (batch, T) → Embedding → (batch, T, d).
  • Padding makes every sequence the same length by adding a filler token (id 0). Masking (mask_zero=True in Embedding) tells the RNN to ignore those padded steps. Padding alone does not hide the zeros from the model; masking does.
  • return_sequences=False (default): output = last hT only (many-to-one). True: output = every ht (shape batch×T×H), needed for stacking RNNs or per-step outputs.
  • Embedding parameters = vocabulary size V × embedding dimension d.
  • Example: Embedding(d=8) → SimpleRNN(12) → Dense(1, sigmoid): RNN params = 12·(8+12+1) = 252, Dense = 12+1 = 13, plus the embedding V×8.
  • Sentiment example: "not good" vs "not bad": the RNN's state after reading "not" changes how "good"/"bad" is interpreted. A bag of words would treat both identically for "not".

Common mistakes

"A longer sequence needs more weights." No. Weights are shared across time; only the computation grows.
"Each time step has its own network." Unrolling is a drawing convenience; there is one cell.
Sizing Whh as D×H. It is H×H (state → state).
Using yt of every step for sentiment. For many-to-one, use only hT (the last state).
Saying gradient clipping solves vanishing gradients. It only tames exploding gradients.
Confusing padding with masking. Padding makes lengths equal; masking makes the model ignore the padded steps.
Forgetting the 3D input shape (batch, timesteps, features).

How to solve RNN numericals

  1. Forward pass: start with h₀ = 0. For each t: compute a = x_t·W_xh + h_{t−1}·W_hh + b, then h_t = tanh(a). Never skip the tanh.
  2. Output: many-to-one → apply W_hy, b_y and g to h_T only.
  3. Parameters: H(D+H+1) for the recurrent layer, O(H+1) for the output layer, V·d for an embedding. T never appears.
  4. Shapes: (batch, T, D) in; many-to-one out (batch, H) or (batch, O) after Dense; return_sequences=True gives (batch, T, H).
  5. Gradient over many steps: multiply the per-step factors: factor^(T−1). <1 vanishes, >1 explodes.

15 · LSTM, GRU & Bidirectional RNNs gates · cell state · additive update · parameters · past+future
In one minute

A vanilla RNN squeezes its memory through tanh(W h) at every step, so old information fades. LSTM adds a separate cell state ct (a conveyor belt of memory) controlled by three gates: forget (what to erase), input (what to write), output (what to reveal as ht). The key line is the additive update ct = ft⊙ct−1 + it⊙c̃t. GRU is a lighter version with two gates (update, reset) and no separate cell state. A Bidirectional RNN runs one RNN forward and one backward and concatenates them, so each position sees both past and future (but cannot be used when the future is unavailable).

15.1 Why gates? The idea in plain words

A plain RNN has to overwrite its whole memory at every step. A gate is a number between 0 and 1 (from a sigmoid) that multiplies a vector element-wise: 0 = block completely, 1 = let everything through. With gates the network learns when to keep, write and read memory, so useful information can survive for many steps.

15.2 LSTM (Long Short-Term Memory)

Two things flow through time: the hidden state ht (short-term, what is exposed) and the cell state ct (long-term memory). Let [ht−1, xt] mean the two concatenated (size H + D).

LSTM equations forget gate ft = σ( Wf [ht−1, xt] + bf ) how much of the OLD memory to keep input gate it = σ( Wi [ht−1, xt] + bi ) how much of the NEW candidate to write candidate c̃t = tanh( Wc [ht−1, xt] + bc ) the proposed new content (in −1..1) cell update ct = ft ⊙ ct−1 + it ⊙ c̃t (⊙ = element-wise product) output gate ot = σ( Wo [ht−1, xt] + bo ) how much of the memory to reveal hidden state ht = ot ⊙ tanh( ct ) 4 blocks (f, i, c̃, o), each with a weight matrix H×(D+H) and a bias H parameters = 4 · H · (D + H + 1) (4 × a simple RNN)
  • Gates use sigmoid (0..1, "how much"). The candidate and the output squashing use tanh (−1..1, "what value").
  • Why it fixes vanishing gradients: along the cell state, ∂ct/∂ct−1 = ft (a gate value), not a repeated multiplication by a weight matrix and tanh′. If the forget gate stays near 1, the gradient flows almost unchanged for many steps: a gradient highway. The update is additive (+), not a full overwrite.
  • Forget-gate bias trick: initialise bf to about 1 so the network starts by remembering.
  • LSTM can still suffer from exploding gradients (clipping is still used), and is much better but not perfect on very long sequences.
  • Number of things passed between steps: two (h and c). For output, ht is used.

15.3 GRU (Gated Recurrent Unit)

A simpler cousin of the LSTM: no separate cell state (only ht) and two gates. It merges "forget" and "input" into one update gate and adds a reset gate that decides how much past to use when proposing new content.

GRU equations update gate zt = σ( Wz [ht−1, xt] + bz ) reset gate rt = σ( Wr [ht−1, xt] + br ) candidate h̃t = tanh( Wh [ rt ⊙ ht−1, xt ] + bh ) new state ht = (1 − zt) ⊙ ht−1 + zt ⊙ h̃t (a blend of old and new) 3 blocks (z, r, h̃) → parameters = 3 · H · (D + H + 1) (3 × a simple RNN, 25% fewer than an LSTM)
Convention warning: some books write ht = zt⊙ht−1 + (1−zt)⊙h̃t (z means "keep old"). The idea is the same: z decides the blend of old versus new. In an exam, use the formula given in the question.
  • Reset gate rt ≈ 0: ignore the past when proposing new content (like starting afresh). Update gate zt ≈ 0 (this convention): copy ht−1 unchanged, giving the same gradient highway as the LSTM's forget gate.
  • Fewer parameters and faster to train than LSTM; accuracy is usually similar. No output gate and no cell state.

15.5 Bidirectional RNNs

Sometimes the meaning of a word depends on what comes after it ("He said Teddy bears are on sale" vs "Teddy Roosevelt was president"). A bidirectional RNN runs two independent RNNs over the same sequence: one forward (x₁ → xT), one backward (xT → x₁). At each step their hidden states are concatenated.

ht = [ ht→ ; ht← ] size = 2H (if each direction has H units) parameters = 2 × (those of one direction) e.g. BiLSTM = 2 · 4H(D+H+1) The next layer receives 2H inputs per step (Dense after a BiRNN has 2H input weights per unit).
  • Good for: classification of a complete text, tagging (NER, POS), speech recognition on a recorded clip, and as an encoder in seq2seq.
  • Cannot be used when the future is not available: real-time/streaming prediction, forecasting the next value, and autoregressive generation / language modelling (the backward pass would "see the answer"). The decoder must be unidirectional.
  • Many-to-one with a BiRNN: take [hT→ ; h1←] (the end of the forward pass and the end of the backward pass, which is at position 1).
  • It does not fix vanishing gradients by itself (use BiLSTM/BiGRU), and it doubles compute and parameters. It is not two copies with shared weights: the two directions have separate weights.
  • Keras: layers.Bidirectional(layers.LSTM(H)), default merge_mode='concat' (alternatives: sum, mul, ave).

Common mistakes

Saying the LSTM cell state and hidden state are the same. c is the long-term memory; h = o ⊙ tanh(c) is the exposed output.
Using tanh for gates. Gates are sigmoids (0..1). The candidate uses tanh.
Writing ct = ft⊙c̃t + it⊙ct−1. The forget gate multiplies the OLD cell, the input gate multiplies the NEW candidate.
Counting 4 gates in an LSTM. 3 gates, but 4 weight blocks (the candidate is the 4th).
GRU parameters = 4H(D+H+1). It is 3H(D+H+1).
Believing a BiLSTM has the same parameters as an LSTM. It has exactly twice as many (and 2H outputs).
Using a BiRNN for next-word prediction or real-time forecasting. The future is not available there.

How to solve LSTM / GRU / BiRNN numericals

  1. Parameter count: RNN = H(D+H+1); GRU = 3×; LSTM = 4×; bidirectional = 2× of the chosen cell. (D = input features, H = units per direction.)
  2. LSTM step: compute (or read) f, i, c̃, o. Then c = f·c_prev + i·c̃, then h = o·tanh(c). Do the cell BEFORE the hidden state.
  3. GRU step: h = (1−z)·h_prev + z·h̃ (check which convention the question uses).
  4. Sigmoid values to remember: σ(0) = 0.5, σ(1) = 0.7311, σ(2) = 0.8808, σ(−1) = 0.2689. tanh(0.5) = 0.4621, tanh(1) = 0.7616.
  5. Output sizes: BiRNN output per step = 2H; Dense after it gets 2H inputs.

16 · Text Representation: Tokenization, BoW, TF-IDF pipeline · tokens · bag of words · TF · DF · IDF · cosine
In one minute

Neural networks eat numbers, not words. The text pipeline is: raw text → preprocessing → tokenization → vectorization → model. Tokenization cuts text into tokens (words, characters or subwords). Bag of Words (BoW) turns a document into a vector of word counts over the vocabulary (order lost, sparse, no meaning). TF-IDF re-weights counts so that frequent-in-this-document but rare-in-the-collection words score high and words found everywhere ("is", "the") score near zero.

16.1 The text pipeline

raw text → preprocessing (clean) → tokenization (split) → vectorization (numbers) → model "Visit https://x.co!! NLP is FUN." → "visit nlp is fun" → [visit, nlp, is, fun] → BoW / TF-IDF / embeddings

16.2 Preprocessing

Typical steps: lowercase, remove URLs, remove punctuation/special characters, collapse extra spaces, (sometimes) remove stop-words, stemming/lemmatisation.

Preprocessing is task-dependent. Lowercasing turns "US" (country) into "us" (pronoun). Removing "!" can destroy sentiment ("great!!!"). Removing stop-words deletes "not" and flips sentiment ("not good" → "good"). There is no universal recipe.

16.3 Tokenization

A token is the unit the model works with. Tokenization = splitting text into tokens, then mapping each token to an integer id using a vocabulary.

  • Naive text.split() splits on spaces only: "wait!" stays glued to the punctuation and "can't" stays as one token.
  • Regex / wordpunct_tokenize separates punctuation: "can't" → ['can', "'", 't']. So the tokeniser changes the vocabulary and the counts.
  • Vocabulary size = number of distinct tokens kept. It sets the width of BoW/TF-IDF vectors and the first dimension of an embedding matrix.
  • Special ids: <PAD> (padding, usually 0), <UNK> (unknown word), sometimes <SOS>/<EOS>.
  • The vocabulary is built from the training data only. Words that appear only in test data are OOV.

16.4 One-hot vectors (the starting point)

Give every token a vector of length V with a single 1: "cat" = [0,0,1,0,…]. Problems: V can be 50,000 (huge), almost all zeros, and every pair of words is equally far apart ("cat" is as unrelated to "kitten" as to "car"). Embeddings (Topic 17) fix this.

16.5 Bag of Words (BoW)

Build the vocabulary from the corpus. Represent each document by a vector of length V whose j-th entry is how many times word j occurs in the document.

corpus: D1 = "NLP is useful" D2 = "NLP is interesting" D3 = "Python is useful" vocabulary (sorted, as scikit-learn does): [interesting, is, nlp, python, useful] V = 5 interesting is nlp python useful D1 0 1 1 0 1 D2 1 1 1 0 0 D3 0 1 0 1 1
  • Vector length = vocabulary size V (not document length). Matrix shape = (documents × V).
  • Word order is lost. "dog bites man" and "man bites dog" have identical BoW vectors. "not good" and "good not" too.
  • No meaning: "car" and "automobile" are different, unrelated columns.
  • Sparse and high-dimensional: mostly zeros. Stored as sparse matrices.
  • Variants: binary BoW (1 if present), count BoW, n-grams (bigrams like "not good" bring back a little order but the vocabulary explodes).
  • Long documents have larger counts just because they are longer, and very common words dominate the counts. TF-IDF addresses this.
  • scikit-learn detail: CountVectorizer lowercases and its default token pattern keeps only tokens of 2+ letters (so "a" and "I" are dropped).

16.6 TF-IDF

Idea: a word is important for a document if it appears often in that document (TF) but in few documents overall (IDF). Words like "is" or "the" appear everywhere, so they carry no information about which document it is.

TF(t, d) = (number of times t appears in d) / (total number of terms in d) (term frequency) DF(t) = number of DOCUMENTS that contain t (a document counts once, however many times t appears) IDF(t) = ln( N / DF(t) ) N = total number of documents (textbook / manual form) TF-IDF(t, d) = TF(t, d) × IDF(t) scikit-learn TfidfVectorizer differs: TF = raw count, IDF = ln( (1+N) / (1+DF) ) + 1, then each document vector is L2-normalised → the numbers are different from the manual ones, and a word in every document does NOT become 0.

Worked on the 3-document corpus (N = 3). Each document has 3 terms, so TF = 1/3 = 0.333 for each present word.

Common mistakes

Counting a word once per document for TF. TF uses the count inside the document; DF counts documents.
DF = total occurrences in the corpus. No: it is the number of documents containing the word.
Saying BoW keeps word order. It does not; "dog bites man" = "man bites dog".
Expecting manual and sklearn TF-IDF to match. sklearn smooths the IDF, uses raw counts and L2-normalises.
Thinking IDF is big for common words. IDF is big for RARE words.
Building the vocabulary on train + test. Fit it on the training set only (leakage).
Believing TF-IDF understands synonyms. "car" and "automobile" are still unrelated columns.

How to solve BoW / TF-IDF numericals

  1. Step 1: tokenise exactly as told (lowercase? remove punctuation?). List the vocabulary (usually sorted alphabetically) and count V.
  2. BoW vector: for each document, write the count of every vocabulary word. Length = V.
  3. TF: count of the word ÷ total tokens in that document (not ÷ V).
  4. DF: number of documents containing the word. IDF = ln(N/DF) unless another formula is given.
  5. TF-IDF = TF × IDF. A word present in every document gets IDF = 0 with the manual formula, so its TF-IDF is 0.
  6. Cosine similarity: dot product ÷ (product of lengths).

17 · Word Embeddings & CBOW dense vectors · embedding matrix · CBOW · skip-gram · applications
In one minute

A word embedding is a short, dense vector (for example 50 to 300 numbers) that represents a word so that words used in similar contexts get similar vectors. All embeddings live in one table, the embedding matrix E of shape V × d; "looking up" a word means reading one row. CBOW (Continuous Bag of Words) learns E with a self-supervised game: use the surrounding words (context) to predict the centre word. After training, you keep E and throw the game away. Embeddings then feed RNN/LSTM/GRU/CNN/Transformer models or are averaged into a sentence vector for classifiers.

17.1 Why we need embeddings

One-hot and BoW/TF-IDF vectors are huge (size V), sparse, and treat every word as unrelated to every other. We want the opposite: small, dense, and meaningful (distance = similarity). The guiding idea is the distributional hypothesis: "a word is known by the company it keeps." "Cat" and "dog" appear in similar contexts (the, pet, feed, my…), so they should get nearby vectors.

17.2 The embedding matrix and the lookup

E has shape V × d (one row per vocabulary word, d numbers per row) word id i → vector = row i of E (a LOOKUP, no multiplication needed) equivalent to: one-hot(i) (1×V) × E (V×d) = row i (the one-hot just selects a row) Embedding parameters = V × d e.g. V = 10,000, d = 300 → 3,000,000
  • The word id is only an index, not a magnitude. Id 2 does not mean "bigger" than id 1.
  • E starts random. It becomes meaningful only after training (CBOW/skip-gram, or end-to-end with your task). Pretrained embeddings (word2vec, GloVe, fastText) can be loaded into the layer: this is transfer learning for text (freeze them or fine-tune).
  • nn.Embedding(V, d) (PyTorch) / layers.Embedding(V, d) (Keras) is exactly this lookup table.

17.3 CBOW: predict the centre word from its context

Self-supervised: no human labels. The labels come from the text itself (the missing centre word). Take a sentence, slide a window of size w, hide the centre word, and ask the model to guess it from the 2w surrounding words.

sentence: "we love natural language processing" window w = 2 centre word = natural context (input) = [we, love, language, processing] target (label) = natural CBOW forward pass 1. word ids of the 2w context words 2. look up their vectors in E (2w × d) 3. average them (1 × d) ← this is the "bag": order is ignored 4. linear layer d → V logits z (1 × V) 5. softmax probabilities p (1 × V) over the whole vocabulary 6. loss = cross-entropy = −log p(true centre word) 7. backprop updates E and the output layer; repeat over the corpus

  • Average = ( (0.5+0.3+0.6+0.3)/4, (0.2+0.6+0.4+0.8)/4, (0.4+0.5+0.2+0.7)/4 ) = (0.425, 0.500, 0.450).
  • Suppose the linear layer outputs logits [0.30, 0.40, 1.40, 0.60, 0.50]. The softmax is [0.130, 0.144, 0.391, 0.176, 0.159].
  • If the true centre word is index 2: loss = −ln(0.391) = 0.939.
  • Gradient of the loss w.r.t. the logits = p − onehot = [0.130, 0.144, −0.609, 0.176, 0.159]: push the true logit up, the others down.
  • Number of training examples: a sentence of L words with window w gives L − 2w (centre, context) pairs when only full windows are used (Python: range(w, L−w)). 8 words and w = 2 → 4 pairs.
  • Parameters: embedding V·d + output layer (d·V + V) = V(2d + 1). Original word2vec keeps two V×d matrices (input and output vectors); the output one is discarded and E is kept.
  • Averaging is why it is a "bag": context word order is lost.
  • The softmax over V words is expensive for large V → tricks like negative sampling or hierarchical softmax (not required here, but good to name).

  • Analogies: king − man + woman ≈ queen (vector arithmetic captures relations).
  • Sentence / document vector: mean of its word vectors (still loses order) → feed to logistic regression, SVM or a small MLP.
  • Input layer of sequence models: token ids → Embedding → RNN/LSTM/GRU/CNN/Transformer. Embeddings can be learned from scratch with the task or initialised from pretrained vectors.
  • Other applications: search and recommendation (item2vec), clustering words, named-entity recognition, machine translation, question answering.

17.6 Limitations

  • One vector per word: "bank" (river) and "bank" (money) share one vector. Contextual embeddings (ELMo, BERT) fix this by giving a different vector in each sentence.
  • Out-of-vocabulary words have no vector (fastText helps with subword pieces).
  • Averaging loses order (CBOW and averaged sentence vectors).
  • Needs a large corpus; embeddings also absorb biases present in the data.
  • Static: once trained, the vector of a word does not depend on the sentence it appears in.

Common mistakes

Saying CBOW predicts the context from the centre word. That is skip-gram. CBOW: context → centre.
Confusing CBOW with Bag of Words. BoW = sparse document counts; CBOW = a task for learning dense word vectors.

18 · Seq2Seq: Encoder–Decoder & the Bottleneck context vector · teacher forcing · decoding · bottleneck
In one minute

Some tasks map a sequence to a different-length sequence with no word-for-word alignment (translation, summarisation, chat). Seq2Seq solves this with two RNNs: an encoder reads the whole input and compresses it into a context vector (its final hidden state), and a decoder generates the output one token at a time starting from that vector. The weakness is the context-vector bottleneck: a single fixed-size vector must hold the meaning of a sentence of any length, so long inputs get squashed and forgotten. Attention (next topic) is the fix.

18.1 Why a plain RNN is not enough for translation

A normal RNN (Topic 14) produces an output at each input step: input and output have the same length and are aligned (POS tagging). Translation breaks both assumptions:

  • Lengths differ: "I love cats" (3 words) → "J'aime les chats" (4 tokens).
  • Order differs: "European Economic Area" → "zone économique européenne" (reordered).
  • The first output word may depend on the last input word, so the model must read the whole input before writing anything.

Solution: split the job in two: first understand (encode), then speak (decode).

18.2 Encoder–decoder architecture

ENCODER (RNN / LSTM / GRU): x₁ → x₂ → … → xT reads the entire source sentence, one token at a time final hidden state (and cell state for an LSTM) = context vector c (a vector of size H) DECODER (RNN / LSTM / GRU): initial state = c input at step 1 = <SOS> → predicts word y₁ input at step t = (previous word) → predicts yt (a softmax over the TARGET vocabulary at every step) stops when it predicts <EOS>
  • Two separate networks with their own weights (and usually their own embeddings and vocabularies: source Vsrc and target Vtgt).
  • The context vector is the only link between them in the basic model. Its size equals the encoder's hidden size H and does not depend on the length of the input.
  • Variants: pass c as the decoder's initial hidden state (most common), or also feed c into every decoder step.
  • The encoder is often bidirectional (it may see the whole source). The decoder must be unidirectional (it generates left to right and cannot see future words).
  • The decoder's hidden size must match the vector it receives (or a linear layer maps between them).
  • Special tokens: <SOS>/<START>, <EOS>/<END>, <PAD>, <UNK>.

18.3 Training: teacher forcing

During training the decoder is given the correct previous word (not its own possibly wrong guess) as input at every step. This is teacher forcing; it makes training fast and stable and lets all steps be computed from known data.

  • Loss = sum (or mean) of the cross-entropy over all decoder steps, each −log p(correct word).
  • Decoder steps = target length + 1 (the <EOS>). The decoder input is the target shifted right by one position.
  • At inference there is no teacher. The decoder feeds back its own previous prediction; one wrong word can derail the rest ("exposure bias").
Training ≠ inference. Teacher forcing (ground truth fed in) is used ONLY in training. At test time the previous output is fed back and generation stops at <EOS> or a maximum length.

18.4 Decoding at inference: greedy vs beam search

  • Greedy: at each step take the single most probable word. Fast but short-sighted.
  • Beam search (beam width k): keep the k best partial sentences at each step, scoring by the product of probabilities (sum of log-probabilities). Finds better overall sequences; k = 1 is greedy.

Example: step 1: A (0.6), B (0.4). After A the next word is x (0.5) or y (0.5); after B it is x (0.9) or y (0.1). Greedy: A then x → 0.6×0.5 = 0.30. Beam with k = 2 also tracks B: B then x → 0.4×0.9 = 0.36, which is better overall.

18.5 The context-vector bottleneck

Everything the decoder will ever know about the source is one vector of fixed size H, however long the sentence is. A 5-word and a 50-word sentence are squeezed into the same number of values.

  • Information loss: details, especially from early words, are overwritten (the vanishing-memory issue of RNNs again).
  • Performance falls as sentences get longer (quality is fine for short sentences, drops sharply beyond ~20 words).
  • The decoder uses the same summary for every output word, though each output word needs a different part of the input.
  • Quick patches: bigger H, LSTM/GRU, reversing the source sentence. They help a bit but do not remove the bottleneck.
  • The real fix is attention: keep all encoder hidden states h₁…hT and let the decoder look at the relevant ones at each step. In the original attention paper (RNNsearch, 2014), BLEU on long English→French translation rose from 26.71 (plain encoder–decoder) to 34.16 (with attention).

18.6 Remaining problems even with attention (why Transformers)

  • The encoder and decoder are still RNNs: sequential (slow, cannot parallelise over positions) and distant words are linked through long chains (n−1 steps).
  • Transformers use self-attention to connect any two words in 1 step and to process all positions in parallel (previewed at the end of Topic 19).

Common mistakes

Saying the context vector grows with the input length. It has a fixed size H.
Using teacher forcing at test time. It is a training-only trick.
Thinking encoder and decoder share weights. They are separate networks (often with different vocabularies).
Making the decoder bidirectional. It generates left-to-right; the future does not exist yet.
Forgetting the <EOS> step when counting decoder steps/targets.
Calling the bottleneck an exploding-gradient issue. It is an information-capacity issue (one fixed-size vector).

19 · Attention: Bahdanau, Luong & Transformer Preview scores · softmax weights · context vector · additive vs multiplicative · self-attention
In one minute

Attention lets the decoder look back at all encoder states and focus on the relevant ones for each output word. For decoder step t: (1) score every encoder state hi against the decoder state, (2) softmax the scores into weights αt,i that are ≥ 0 and sum to 1, (3) build a context vector ct = Σ αt,i hi (a weighted average), a different one for every output word. Bahdanau (additive) scores with a small network vᵀ tanh(W₁s + W₂h) using the previous decoder state. Luong (multiplicative) scores with a dot product sᵀh (or sᵀWh) using the current decoder state. The Transformer then drops the RNN completely and uses attention only.

19.1 The idea (why it works)

A human translator does not memorise the whole sentence and then write from memory; they glance back at the relevant source words while writing each target word. Attention does that. It removes the context-vector bottleneck of Topic 18: the encoder keeps all its hidden states h₁…hT (no longer only the last one) and the decoder takes a fresh weighted mix of them at every step.

Attention, three steps (decoder step t, encoder states h₁ … hT) 1. scores et,i = score( decoder state , hi ) one number per source position i 2. weights αt,i = softmaxi( et,i ) = exp(et,i) / Σj exp(et,j) α ≥ 0 and Σi αt,i = 1 3. context ct = Σi αt,i · hi a weighted sum (same size as hi) then the decoder uses ct together with its own state to predict yt.
  • Soft attention: a smooth weighted average, therefore differentiable. It is trained by ordinary backprop together with the rest of the model; there is no separate alignment labelling. The alignment is learned.
  • The weights form an attention matrix (target positions × source positions). Each row sums to 1 (one row per output word); columns do not.
  • Example: when writing "zone" in "European Economic Area" → "zone économique européenne", the weight concentrates on "Area"; the model learns the reordering by itself.
  • Cost: Tout × Tin scores. Results (Bahdanau et al. 2014, long sentences): BLEU 26.71 → 34.16.

19.2 Bahdanau attention (additive, 2014)

The first attention model (RNNsearch). Encoder: usually a bidirectional RNN, hi = [hi→ ; hi←] (so each hi knows the words before and after position i). The score is computed by a small feed-forward network:

Bahdanau (additive / concat) score et,i = vᵀ tanh( Ws st−1 + Wh hi ) st−1 = PREVIOUS decoder hidden state Ws : da × ds Wh : da × dh v : da (da = size of the attention hidden layer) then αt,i = softmax(et,i), ct = Σ αt,i hi the context ct is fed INTO the decoder RNN step: st = RNN( st−1 , [ yt−1 ; ct ] ) extra parameters = da·ds + da·dh + da (no biases)
  • "Additive" because the two projected vectors are added inside the tanh.
  • Works even when the decoder and encoder sizes differ (Ws and Wh map both into da).
  • Order of operations: previous state st−1 → attention → context ct → RNN step → new state st → output.

19.3 Luong attention (multiplicative, 2015)

A simpler, faster variant. The decoder RNN runs first to get the current state st, and then attention is applied on top of it.

Luong score functions (st = CURRENT decoder hidden state) dot: et,i = stᵀ hi no parameters (needs ds = dh) general: et,i = stᵀ W hi W : ds × dh (multiplicative with a learned matrix) concat: et,i = vᵀ tanh( W [ st ; hi ] ) (this one is the additive form) then αt,i = softmax(et,i), ct = Σ αt,i hi attentional state: s̃t = tanh( Wc [ ct ; st ] ) → yt = softmax( Wy s̃t )
  • "Multiplicative" because the score is a product (dot/bilinear), not a tanh of a sum.
  • Order: RNN step first → st → attention → context ct → combine with st → output. The context is not fed into the RNN step (in the basic version).
  • Dot product is the cheapest (one matrix multiply, no extra parameters). It also scales to the Transformer.
  • Luong also proposed global attention (all source positions) versus local attention (a window around a predicted position, cheaper for long inputs).

"Attention weights don't need to sum to 1." They are a softmax over source positions, so they do sum to 1 (per decoder step).
Mixing up the two score functions. Additive = vᵀtanh(W₁s + W₂h) (Bahdanau). Multiplicative = sᵀh or sᵀWh (Luong).
Thinking Bahdanau uses the current decoder state. It uses the previous one, st−1. Luong uses st.
Using one context vector for the whole sentence. Attention computes a new ct for every output step.
Summing weights over decoder steps instead of over source positions. Each row (one output word) sums to 1 over the inputs.
Calling attention a replacement of the encoder. In Bahdanau/Luong the encoder RNN stays; only the Transformer removes it.
Forgetting √dk scaling in Transformer attention, or applying the mask after the softmax. The mask (−∞) is applied before the softmax.

D. Final trap checklist

  • Frozen ≠ skipped. Re-compile after changing trainable. Keep BN in inference mode. Fine-tune with a small LR, train the head first.
  • Augmentation: training set only, label-preserving; it does not add independent samples or parameters.
  • RNN: parameters do not depend on T. Whh is H×H. Many-to-one uses hT only. Clipping fixes exploding, not vanishing.
  • LSTM: 3 gates, 4 blocks, additive cell update, ct unbounded. GRU: 2 gates, 3 blocks, no cell state. BiRNN: 2× parameters, 2H outputs, not for real-time or generation.
  • Library conventions: PyTorch LSTM/GRU/RNN and Keras GRU have two biases (+2). Textbook uses +1.
  • BoW and unigram TF-IDF ignore order and meaning. DF counts documents. Word in every document: manual TF-IDF 0, sklearn > 0.
  • CBOW: context → centre, average, V(2d+1) parameters. Not the same as BoW. Static embeddings: one vector per word, OOV has none.
  • Seq2seq: fixed-size context vector regardless of length; teacher forcing only in training; decoder not bidirectional.
  • Attention: weights sum to 1 over the source for each decoder step; Bahdanau = previous state + additive; Luong = current state + product; Transformer scales by √dk and masks before softmax.
